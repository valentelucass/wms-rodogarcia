# D21 — contrato backend / runner manual Prumo

Lucas supersede D20 somente para BOOTSTRAP/UPGRADE manual administrativo. Perfil explícito **bootstrap-local**, distinto de migrations D20/runtime. Endpoint fixo TCP **127.0.0.1:1433**, bancos exatos **WMS_DEV/WMS_PROD**, DEV primeiro. `sa` é permitido somente neste launcher; não exigir criação/grant de aplicação para executar o DDL administrativo autorizado. Runtime Java permanece WMS_DEV com conta restrita própria, sem alteração nesta entrega.

Contrato combinado pela leitura de [Prumo](../../database/docs/d21-contrato-flyway.md), antes do código. Filho Maven efêmero recebe somente `WMS_DB_BOOTSTRAP_GUARD=D21_LOCAL_MANUAL_CONFIRMADO`, HOST=127.0.0.1, PORT=1433, NAME=WMS_DEV ou WMS_PROD, USER=sa, PASSWORD, SERVER e INIT_SQL. Senha obtida ocultamente em memória pelo runner: nunca argumento/arquivo/log/ambiente pai/User/Machine. POM referencia PASSWORD somente no parâmetro password do plugin, sem regex/echo do valor; ausência é recusada em validate e senha vazia pelo runner antes do filho.

Propriedades separadas `wms.bootstrap.skip=true` e `wms.bootstrap.initSql=THROW 51021,...` por padrão. Somente marcador exato ativa a fonte `${env.WMS_DB_BOOTSTRAP_INIT_SQL}`; fonte não vazia e SERVER são obrigatórios em validate. Mesmo que habilitem skip num goal direto sem marcador, initSql conserva THROW antes do schema/histórico. Fonte transitória construída/escapada pelo runner confere SETs e identidade real ServerName/DB_NAME/ORIGINAL_LOGIN=sa em cada conexão, com recusa explícita de valores NULL. Não interpolar servidor/login/segredo cru no SQL do POM.

POM fixa TLS validado, wms/defaultSchema, flyway_schema_history, filesystem `${project.basedir}/../database/migrations`, placeholder wmsDatabase pelo banco exato e proteções cleanDisabled/baselineOnMigrate/validateOnMigrate/outOfOrder/naming. Não define target nem enumera V1–V9. Runner usa exclusivamente validate/info/migrate, settings vazios, configFiles vazio e recusa clean/baseline/repair, debug/trace, perfis extras, env/argumentos/configurações/overrides recebidos. Marcador não é segredo e POM não promete impedir adulteração maliciosa do executor.

Cada chamada autorizada inclui `validate` Maven, `-Pbootstrap-local` e `-Dwms.bootstrap.skip=false`, em filho separado. Pré-Flyway-validate usa **somente** `-Dflyway.ignoreMigrationPatterns=*:pending`; migrate/pós-validate/info usam `-Dflyway.ignoreMigrationPatterns=` para limpar o default *:future. São argumentos fixos do runner, não overrides livres do usuário. Interromper no primeiro exit não zero; erro DEV impede PROD. Capturar saída sem repassar texto bruto nem efetuar debug/dump de configuração com senha. validate confere histórico/checksums, não drift DDL universal.

O perfil bootstrap-local fixa a propriedade Maven `flyway.ignoreMigrationPatterns` vazia e liga o parâmetro do plugin a ela: pré-validate recebe a exceção fixa *:pending, pós retorna ao vazio explícito. [Flyway oficial](https://documentation.red-gate.com/fd/flyway-ignore-migration-patterns-setting-277579002.html) documenta default *:future e limpeza por string vazia; [Maven oficial](https://maven.apache.org/guides/mini/guide-configuring-plugins.html) suporta valor XML para arrays. Configurações efetivas foram inspecionadas sem PASSWORD no ambiente, evitando dump de senha. **25/25 fixtures offline aprovadas**: base23, duas adicionais e reconferência somente das cinco afetadas pelo reforço NULL de Prumo, sem somar repetições.
